# OUTIE × OurVerse 合并方案（讨论稿）

2026-09-28 更新 · Phase 1 已完成并入本仓库；三向决策已定：对外统一命名 OUTIE / 保留酒吧数据作冷启动 / 先网页后 iOS

## 一、总原则

**OUTIE 是产品，OurVerse 是引擎。**
用户只看到一个 App：OUTIE，像素宠物 + 线下打卡。
OurVerse 的全部能力（地点、打卡围栏、照片流、身份）降级为 OUTIE 内部的三个模块，
原仓库和部署可以沿用，但对用户不可见。

反过来不成立：不在 OurVerse 里"加一个宠物功能"，
而是 OurVerse 整体被 OUTIE 吸收——否则会变成两个气质打架的产品拼在一起。

## 二、模块映射（OurVerse 现有能力 → OUTIE 里的角色）

| OurVerse 现状 | 在 OUTIE 里的身份 | 需要的改造 |
| --- | --- | --- |
| Bar / 高德 POI（酒吧+经纬度） | 「地点」spot：活动点位、城市兴趣点 | 概念从酒吧泛化为任意地点；加活动归属字段 |
| `POST /bars/checkin` + 200m 围栏 | 打卡引擎（OUTIE 首版做不了定位，直接继承） | 打卡成功后触发 OUTIE 发造型（去重逻辑加活动维度） |
| 照片上传 / 附近照片流 / 匿名投递 | 「现场痕迹」：打卡照片 + 宠物合成图都落在这里 | 加宠物合成图的内容类型；像素边框在客户端做 |
| JWT + GitHub 登录 + anonymousId | 身份模块：OUTIE 匿名起步，可选绑定账号 | OUTIE 的 localStorage 匿名态与 anonymousId 对齐 |
| 高德逆地理 / IP 定位 | 「今天的活动」定位推荐 | 不变 |
| iOS SwiftUI App | 未来的 OUTIE 壳（Phase 3） | UI 全部重做（见美工节） |

后端改造量评估：新增 pets / events 两张表 + `/api/outie/*` 若干路由 + CORS 白名单加 OUTIE 域名。
OurVerse 现有功能不动、数据不迁，风险低。

## 三、美工重设计

### 设计系统（全局统一，OUTIE 已有雏形）

- 色板：纸底 `#efecdf` + 墨 `#26241c` + 四个低饱和点缀色（蓝红黄绿）。全 App 只许用这套。
- 字：拉丁/数字用点阵字（已有），中文系统字体；禁用圆体、手写体、渐变。
- 组件：硬边框 2px、无圆角、无阴影；进度=印章；反馈=步进跳帧动画。
- **现实照片的处理是关键**：照片本身是真实的（不像素化），
  但装进像素边框、盖活动像素印章、配点阵日期。
  "真实照片 × 像素框架"的反差就是这个产品的视觉签名。

### 地图（重点重设计项）

三个方案：

- **方案 A：手绘像素场地图**。每场活动一张 8-bit 平面图（美术出图或主办方摆点生成），
  点位是像素标记。100% 风格可控，最适合"一场活动三个点"的主场景；缺点是不覆盖城市级浏览。
- **方案 B：真实地图 + 像素皮肤**。保留高德数据，渲染层做纸感灰度样式
  （MapLibre 自制样式或高德个性化模板调灰），叠 2×2 网格与像素 marker。
  覆盖全城；缺点是样式调教有上限，做到"真 8-bit"需要瓦片级重绘。
- **方案 C（推荐）：A+B 分场景用**。
  活动详情页 → 方案 A 的像素场地图（主战场，风格担当）；
  「附近/城市」页 → 方案 B 的纸感地图（功能担当，降饱和不抢戏）。

### 美工交付物清单（需要美术或 AI 生图产出）

1. 场地像素地图模板（可复用，主办方换点位即可）×1 套
2. 城市/纸感地图样式规格（色板映射表）
3. 点位标记（未解锁/已打卡/限定点）×3 状态
4. 宠物在照片里的贴纸素材（含影子/落地感）×5 形态
5. 打卡成功、解锁、进化的全屏动效帧（8-bit，步进播放）

## 四、App 形态与路线

- **Phase 1（后端 + 网页，~1 周量级）**
  OurVerse 后端加 outie 模块；线上 OUTIE 网页接真打卡（围栏校验）、
  匿名身份落库；打卡后照片贴纸合成（无 AI 版）。地图先用方案 A 的场地图。
- **Phase 2（地图 + 照片流，~2 周量级）**
  方案 B 纸感城市地图上线；贴纸照片进 OurVerse 照片流（互相导流）；
  AI 生图合成做开关灰度。
- **Phase 3（iOS 壳，后置）**
  OurVerse iOS 重做成 OUTIE：宠物上桌面小组件、打卡推送、相机直出合成。
  网页 PWA 先行验证，别急着写原生。

## 五、要拍板的三件事

1. **产品命名**：对外统一叫 OUTIE？（建议是；OurVerse 只留作仓库名）
2. **OurVerse 现有酒吧数据**：保留为 OUTIE 的第一批城市地点，还是清掉只做活动？
   （建议保留，现成的冷启动内容）
3. **先做哪个端**：建议网页 PWA 跑通 Phase 1/2 再动 iOS。
